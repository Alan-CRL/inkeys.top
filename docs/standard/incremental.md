---
title: 增量写入
---

UInk 允许在不修改此前字节的前提下，把完整的新块追加到文件末尾。增量写入用于实时保存和崩溃恢复，不替代最终完整保存。

## 可以追加的内容

只允许向文件末尾当前 Device 的最后一个 Canvas 追加：

- 一条已经抬笔并完整结束的 [Ink](blocks/ink)；
- 一个新插入且无需修改历史顺序的 [Media](blocks/media)；
- 当前 Device 的新 [Canvas](blocks/canvas)，随后再逐个追加其完整内容块；
- 一个新 [Device](blocks/device)及其首个 Canvas。

每完成一条墨迹，无论是普通笔、荧光笔还是擦除墨迹，都可以把完整 Ink Map 追加到末尾。尚未完成的轨迹不得写入；MessagePack Map 不允许只写一部分后等待后续补齐。

追加后必须按固定偏移更新 Header 的 `deviceNum`、`pageNum` 和 `time`。仅追加 Ink/Media 时，通常只需更新时间；追加 Device 或新逻辑页时还需更新相应计数。

## 顺序要求

- 新内容的 `contentId` 必须承接当前 Canvas 的 Ink/Media 共享序列。
- `undoId` 不得小于此前内容的 undoId。
- 不得在文件末尾重复写一个旧 canvasId 并要求读取器合并。
- 如果目标不是文件末尾最后一个 Canvas，则必须完整重写。

## 必须完整重写的情况

以下操作会改变历史内容或使顺序不再可靠：

- 撤回或重做；
- 返回旧页、旧图层或更早 Device 修改；
- 普通板擦切断已经保存的旧墨迹；
- 修改、移动、删除既有 Media；
- 改变页面或图层结构、编号或排序；
- 修改 Device 几何或宿主绑定；
- 任何无法保证追加结果与当前画面一致的情况。

完整重写时必须：

1. 只保存当前有效内容，移除已撤回块；
2. 重新整理各 Canvas 的 `contentId`、`undoId` 和 Canvas 内编号；
3. 重新计算 Header.deviceNum 和 Header.pageNum；
4. 更新 Header.time；
5. 保持 Header.guid 不变。

::: warning 擦除模式不同
擦除墨迹是新的完整 Ink，可以直接追加；普通板擦会改变旧墨迹并生成剩余片段，因此必须完整重写。
:::

## Canvas 结束与翻页

用户正常完成当前页并创建下一页时，可以追加新的 Canvas。用户翻回已经写入的页面修改时，必须完整重写；不能在文件末尾追加一个重复 Canvas 来模拟补丁。

空白 Canvas 也可以追加并保存，它表示已经创建但尚未绘制的页面或图层。

## 推荐保存策略

软件运行期间可以持续增量追加，以减少崩溃导致的数据丢失。正常关闭、显式保存或出现结构性修改时，建议完整重写一次，以校验编号、计数和顺序。

参见[墨迹主文件](file/main)中的完整作用域和混合顺序规则。
