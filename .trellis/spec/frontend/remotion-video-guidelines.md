# Remotion 视频制作经验

## 适用范围

官网里用 Remotion 制作的循环小视频和演示视频（S1 卡片、S2 场景等）。原生离屏导出的约定见 [native-media-guidelines.md](./native-media-guidelines.md)。

本文件随制作过程补充。工程在 `media/nh3-remotion/`，怎么预览、改哪里见其中的 README。

## 先定方向，再写代码

1. 先看参考片：用 ffmpeg 每半秒抽一帧拼成总览图，列出它用了哪些手法，再判断哪些适合我们。
   ```bash
   D:/Project/Resource/ffmpeg/ffmpeg.exe -i ref.mp4 -vf "fps=2,scale=400:-1,tile=5x4" -frames:v 2 sheet-%d.png
   ```
2. 用文字给出两三个创意方向让用户选；选定后做静态样张（纯 HTML，按卡片真实尺寸，套用 `home.css` 的令牌），用无界面浏览器截图给用户看。
3. 样张和帧级分镜确认之后才建 Remotion 工程。样张只能确认构图和配色，缓动和节奏要靠测试片。

2026-11 之前的旧片（`media/inkeys3-remotion/`）把整块屏幕照实还原，信息密、没有主角，用户评价很差。之后的片子：一个画面只留一个主角，同一时刻只有一个东西在动。

## 画面约定

- 颜色、圆角、缓动取网页的 `--nh3-*` 令牌；视频背景等于所在容器的底色，这样视频看起来是页面的一部分。
- 视频里不放说明文字，说明由网页文字叠加；画面里的示例内容和软件界面用英文。
- 软件主栏整条有 770 个逻辑单位宽，放进小卡片只能露出一段；需要让某个按钮入镜时，滑动主栏，不要缩小整条。
- 主栏必须是 en-US、选择与穿透合并式。
- 网页叠加的文字区里不放会动或高对比的东西；按最长的语言（英文会折成两行）留位置。

## 视线引导

- 界面上有状态变化（按钮被按下、工具切换）时，必须有一个东西把视线从上一个焦点带过去。只靠“同一时刻只有一个东西在动”和按钮自己的反馈不够：观众的眼睛还停在墨迹上，等发现主栏变了已经晚了。纸面上推演看不出这个问题，要在 Studio 里看动起来的效果。
- 做法是指针：画布上用软件自己的画笔光标，主栏上用鼠标箭头，由它串起“写 → 去点按钮 → 到下一处 → 写”。移动走略弯的弧线，起步快、收得慢。
- 把点击和换场绑在同一帧，画面更紧凑。
- 标记文字的墨迹（荧光笔、下划线）起止要贴着文字；“出框”这类创意只用在圈画这种本来就比目标大的笔迹上。
- 节奏的定稿取值（用户先嫌慢，收紧后又嫌书写太快、点击太急）：圈一个标题约 0.8 秒，小圈 0.6 秒，荧光笔 0.5 秒；内容切换 0.3 秒；一道墨迹写完后停 0.35 秒以上指针才动。
- 指针的动作之间要留人的反应时间：到位后停约 0.2 秒再按下，点完停约 0.25 秒再离开，到达落笔处停约 0.15 秒再写。到位就点会显得机械。

## 用镜头讲，而不是把操作演一遍（2026-11-18）

第一张卡片（屏幕批注）让指针写字、点按钮、再写字，等于重做了一段录屏，用户评价平淡。第二张卡片（自由白板）改了做法：

- 先定一个高光时刻，再排其余的内容。白板卡片的高光是“镜头跟着笔尖横移看一笔曲线写出来，再以收笔处为轴拉远”。
- 做出大小对比：特写时内容铺满文字区以下的整张卡片，拉远后才露出屏幕边框。实现是把整块屏幕放进一个可以缩放、平移的舞台（`src/cards/whiteboard/camera.ts`），文字区用一个裁切框挡住。
- 特写时屏幕的边框必须全部在卡片之外，否则会露出半条边。按“对准点的坐标 × 倍率”逐个机位验算。
- 拉远时以笔迹的收笔点为轴缩放，这个点在画面里不动，视线不会丢。
- 倍率按对数插值，推拉的速度看起来才均匀。
- 循环的接缝放在翻页里：结尾翻到空白页并回到开头的机位，首尾是同一个画面。
- 软件做不到的事不能演成功能：白板不能缩放，所以推拉的是连边框在内的整块屏幕；软件翻页没有过渡，片子里的横移只是转场。这两点写在 `Card.tsx` 的开头。
- 小字的笔画只有几十像素，`writePath` 的起笔、收笔和曲率窗口是按一两百像素定的；先把路线放大 5 倍再算速度，算完缩回去（`src/ink/handwriting.ts` 的 `writeSmall`）。
- 手写字形复用 `media/inkeys3-brush-showcase/handwriting-revision/v3` 里的作者路线（贝塞尔控制点），不用字体描边。

## 第二、三张卡片返工得到的经验（2026-11-22）

第二张（自由白板）改了底色，第三张（PPT 演示）整体重做。用户的原话是“出现了大面积的彩色，而网页是比较纯色调的风格”和“分镜和动画都比较意义不明”。

- 网页是纯色调的，画面里不能有大面积的彩色。软件的出厂底色（白板的深绿 `#123B32`）照实用就会出问题；从软件自己的预设里挑接近网页的：浅色版米白 `#F5F1E6`，深色版墨蓝 `#172A46`。彩色只留给墨迹。
- 换了底色就要重新核对笔色的对比度。软件默认的红 `#FF1000` 在墨蓝底上约 3.7:1，偏暗，深色版的强调笔迹改用调色板里的橙 `#FF8B00`；蓝 `#326ED9` 在深色幻灯片上偏暗，深色版用 `#4EA1B7`。
- 缩到卡片大小、不看文字，也要认得出画面里是什么、发生了什么。第一版第三张失败在这里：开场是插图的大特写，看不出是幻灯片；两页画的是同一个东西，看不出翻了页；内容要懂专业知识才看得懂。重做时两页的版式差得很远（大标题加进度线、柱状图），翻页用整页横向推走，分页栏在全景里入镜。
- 一张卡片讲一件说得出口的事。第三张讲的是“激光笔过一会儿自己消失，普通的笔写下的留在这一页上”，这个对比来自用户的提示。只有“圈、翻页、再圈”的流程不算一件事。
- 大改之前先出 3 到 4 帧静态样张给用户看方向，认可后再做动画。样张用的部件直接留作成片的部件。
- 画面里用不上的界面不要画。白板卡片里的主栏没有参与任何动作，用户要求去掉；放映卡片从一开始就只画分页栏。
- 片子和软件的真实行为不一致时，先如实告诉用户，由用户决定，再把取舍和改回去的办法写进 `Card.tsx` 的注释和任务的设计记录。例：软件里切到别的笔的那一刻激光被立即清掉，片子里按用户的要求让它在笔写别处时渐渐熄灭。
- 以前导出的原生图会过时。旧工程里的放映分页栏图在最后一页画的是 End show，当前软件在最后一页仍是 Next；借用旧图之前先对照当前源码，不符就重新导出。

## 软件界面的事实（2026-11-16，`dev` `c06697b1`）

完整报告在 `.trellis/tasks/archive/2026-11/11-16-new-index3-s1-card-motion/research/codex-ui-survey-result.md`。常用的几条：

- 主栏按钮：Select、Soft Pen、Shapes、Erase、Undo、Clear、More、Board、Freeze；主按钮 80×80，按钮 70×70，间距 5。
- 选中色：浅色 `#006A63`，深色 `#58FFEC`，和网页强调色相同。
- 笔型在主栏上的文案：Soft Pen、Hard Pen、Highlight、Laser。
- 定格生效后屏幕上没有额外提示，只有 Freeze 按钮变为选中态；要表达定格就必须让这个按钮入镜。
- 软笔默认红色 `#FF1000`；荧光笔默认品红 `#FF1ECF`、不透明度 35%、竖直方头笔尖。
- 软笔：慢则粗（最多 1.4 倍）、快则细（最少 0.8 倍），起笔不渐粗；笔迹最前端最近 55ms 走过的一段收成笔锋，最细到 30%。
- 白板（2026-11-18，`refactoring/draw` `bcc11421`，报告在同目录的 `codex-whiteboard-survey-result.md`）：出厂底色 `#123B32`，和软件主题无关；点阵可选，点距 24、直径 2、不透明度 0.18；深底上默认笔色是白色；触摸书写不显示光标；翻页立即切换；画布能平移、不能缩放；白板的主栏是 Move、Soft Pen、Shapes、Erase、Undo、Clear、More、Close，左下角另有分页栏。
- 立体图形（Cuboid、Cube、Cylinder、Cone、Prism、Pyramid）只有描边，分两次拖动放置（先底面、再高度）；被挡住的棱是虚线（实段 4 倍线宽、间隔 6 倍线宽）。
- 白板底色的预设（2026-11-22）：`#123B32`、`#172A46`、`#000000`、`#FFFFFF`、`#E5E7EB`、`#F5F1E6`。
- 放映（2026-11-22，`refactoring/drawpad-ui` `866762e0`，报告在 `.trellis/tasks/archive/2026-11/11-19-s1-card3-motion/research/`）：左下角分页栏是拖动柄、Previous、页码（上下两行）、Next，主体 240×80；最后一页时右键仍是 Next，进入结束屏后才变 End show；按下是缩到 0.95 加压暗，没有水波；每页墨迹独立保存，翻回去恢复；页面立即切换。
- 激光笔（同上）：默认红色 `#FF1000`、粗细 5；四层材质（外层漫反射、实体壳、内散射环、宽为三分之一的白芯）；最后一道抬笔后满亮 1.0 秒，再 0.8 秒整条淡出，曲线 `1 − t²(3 − 2t)`；绘制时不显示光标；不进撤销历史、不保存到页面，翻页即清空，切到别的工具也立即清空。

## 笔迹

- 笔迹路线用带时间的采样点手工编排，转弯减速、长弧加速，抬笔时笔还在动。用公式生成的圈加一条向外甩的尾巴，用户一眼就看出不自然。
- 每一帧按“写到此刻为止的采样点”重新计算整条笔迹，实时笔锋才会一直跟在最前端。不要用遮罩去揭开一张写好的终帧。
- 用户对墨迹的四项要求（2026-11-16），每支片子都要逐条自查：
  1. 对位：墨迹和背景里被标记的对象在同一个位置。笔迹坐标从内容的布局常量算出，不各写各的数字。
  2. 笔锋：软笔的笔锋是实时的，书写中每一帧都在最前端。
  3. 颜色：在浅色、深色两版里都清楚。
  4. 速度：像人写的，有快有慢，不匀速。

## 放进网页

- 视频里凡是可以被裁掉的区域（通常是顶部留给文字的纯色区）要在设计时就定好；网页里按宽度铺满、贴底对齐，容器不能比视频更瘦高，这样两侧的主体永远不会被裁。
- 叠在视频上的文字是固定字号，容器越窄文字占比越大。先算出文字不压到画面的最小容器宽度，小于它就换排法（横向滑动或竖排），不要让卡片继续缩小。

## 环境

- 本机是 Windows ARM64。Remotion（4.0.542 仍是如此）的合成器只有 x64 版本，需要便携的 x64 Node 来运行：`media/nh3-remotion/scripts/run.mjs` 会自动选用 `.cache/node-x64/node.exe`；`pnpm-workspace.yaml` 用 `supportedArchitectures` 同时安装 x64 的可选依赖。Studio 预览和渲染都走这个入口。
- 在 Claude 桌面应用里预览 Studio：`.claude/launch.json` 里的 `remotion-studio` 配置（带 `--no-open`，在应用内的浏览器面板里打开）。
- `npm view` 在本机可能长时间无响应，不要用它查版本；直接看已安装的 `node_modules`。
- 批量抽帧时不要把 `run.mjs still` 的输出接到管道里（`| tail`）：渲染结束后管道偶尔不关闭，整个循环会挂住。改成重定向到文件（`> still.log 2>&1 < /dev/null`），并给每帧加 `timeout`。单帧约 16 秒。
- 系统的 `python` 命令有问题，用 `python3`；运行 Trellis 脚本时加 `PYTHONUTF8=1`。需要 numpy 时用 `uv run --no-project --with numpy --with pillow python <脚本>`。
- 在 Bash 里用内联 heredoc 写含中文或引号的脚本容易报 `unexpected EOF`，先把脚本写成文件再执行。
- 无界面截图：Playwright 在 `C:/Users/alan-/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright`，浏览器用系统的 Edge。

## Remotion 里的实现经验

- 笔迹的速度按人手运动的规律生成：速度与曲率的 -1/3 次方成正比（弯得越急走得越慢），再乘上起笔由慢到快、收笔略慢但不停的包络。只给控制点和总时长，速度曲线自动像人写的（`src/ink/path.ts`）。
- 笔迹画成 SVG：每个采样点一个圆，相邻两点之间一个梯形。圆和梯形分成两条路径，各自内部绕向一致，重叠处才不会被抵消成空洞。
- 半透明图层之间做交叉淡化，不能简单地一张淡出一张淡入（中途底色会变淡），也不能叠在一起（底色会变浓）。放进 `isolation: isolate` 的组里，各层用 `mix-blend-mode: plus-lighter`，权重之和为 1，才是严格的线性过渡。
- 文字不同的两张状态图不要交叉淡化，会出现两行字的重影。按软件真实的方式：旧内容缩小淡出，中点换图，新内容放大淡入。
- 从一张半透明的整图里单独缩放某个按钮：把那一格从整图里挖掉（`clip-path` 的 evenodd 路径），在原位放一个组，组内全部按不透明来画（SVG 滤镜把 alpha 提到 1），再给整个组套上主栏的不透明度。直接“垫底色＋叠缩小的按钮”会让底色叠浓，出现一个发白的方块。挖洞的四条边要对齐到渲染后的整像素，否则有接缝。
- 小尺寸画面里软件原本的反馈幅度会看不见（按钮缩到 95% 只动 3 个像素）。要按最终像素重新定幅度。
- 每做完一个部件就用 `still` 抽几帧拼成总览图自查，再放大看细节（笔锋、接缝），不要等整片渲染。
- 给会生长的笔迹加 SVG 模糊滤镜（发光）时，滤镜范围要写成 `filterUnits="userSpaceOnUse"`，按已画出的笔迹外扩固定的距离。默认范围是包围盒的百分比，刚落笔时笔迹接近一条横线，包围盒几乎没有高度，光晕会被齐刷刷截掉（`src/cards/slide-show/Laser.tsx`）。自查时要抽刚落笔的那几帧，只看画完的帧发现不了。
- 镜头在动时不要再单独缩放界面上的一小块（按钮按下缩到 0.95），缩放的边缘会出现接缝；只做压暗。
- 推近的机位要把不相干的界面完整留在画面外，露出半截分页栏比不露更显眼。

## 和 Codex 分工

- 只读的源码调查交给 Codex 效果好：把问题分节列清楚，要求每条结论给出文件和行号，用 `-o` 把最终报告存进任务目录。
  ```bash
  codex exec -C <软件仓库> -m gpt-6.1-sol -c model_reasoning_effort=high -c service_tier=default --sandbox read-only -o <报告路径> - < <任务说明>
  ```
- Codex 的工作区沙箱在本机不能运行 Python，需要运行的脚本由 Claude 执行。
- 软件仓库正在被使用时（有未提交的改动，或 Visual Studio、MSBuild 在运行），不要在里面打补丁和构建。做法（2026-11-18）：`git clone --local --no-checkout` 到 `media/nh3-remotion/.cache/src` 并检出目标提交；从原仓库复制 `VcpkgInstalled/Arm64`、`Package`、`Vcpkg/scripts/buildsystems/msbuild`、`Inkeys/additional/HiMsg`；构建时加 `/t:Inkeys /p:VcpkgManifestInstall=false`。先做一次不打补丁的基线构建（约 10 分钟），适配的构建就是增量的。副本连中间文件约占 2 GB。
- 给 Codex 的任务说明里写明“属于已有的 Trellis 任务、不要新建任务、不要提问”：非交互运行时它的 Trellis 钩子会让它停下来问要不要建任务，白跑一次。
- 原生导出适配这类“照着现有适配改”的工作适合交给 Codex：让它在新目录里复制修改、逐个核对软件符号和安装锚点、列出接下来要执行的确切命令；它不构建不运行，Claude 核对脚本差异后再执行。2026-11-16 这样做的六张主栏状态图一次构建通过。
- 软件仓库的工作区干净、且用户同意时，可以直接在仓库里打补丁构建（2026-11-22 的 `native-slideshow/`）：安装脚本拒绝脏的工作区，结束后按字节还原，`git status` 应为空。
- 构建时不要覆盖 `/p:IntDir`：`Inkeys.vcxproj` 把 `$(IntDir)` 当包含目录，源码里有相对它写的包含路径，改了就报 C1083 和一串模块错误。只给 `/p:OutDir` 一个私有目录。
- 用户明确允许 Fast 时才加 `-c service_tier=fast`。2026-11-22 用 `gpt-6.2-sol`、High、Fast 做的两次只读调查各约 10 分钟，抽查属实；它写的导出适配在去掉 IntDir 覆盖后一次通过。它的结论仍要在源码里核对关键几条。
