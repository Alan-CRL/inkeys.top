# 宣传短片制作经验（S5-A 书写体验）

## 适用范围

官网里用 Remotion 制作的**宣传短片**：有幕标题和功能名大字、多个功能连续展示、约 30 秒循环的片子。第一支是 S5-A“书写体验”（工程 `media/nh3-remotion/src/s5a/`），第七版于 2026-11-23 验收，约 30.9 秒，三语合成都已注册。成片还没有渲染，等官网其余视频都做完后统一渲染、嵌入。

卡片级的小循环视频、通用环境与渲染约定见 [remotion-video-guidelines.md](./remotion-video-guidelines.md)，本文只记宣传片特有的部分。任务记录已归档到 `.trellis/tasks/archive/2026-11/11-22-new-index3-s5a-writing/`（`style-v6.md`、`storyboard-v6.md`、`revision-v7-plan.md`）。

## 定风格：前五轮为什么失败

S5-A 的画风前后做了六轮，前五轮都被否掉：霓虹线框、拟真摄影棚、三套平面样板、照抄参考片、墨蓝倾斜画布。教训：

- **用户给参考片时，只学他点名的那一两个手法。** 第四轮把参考片的表面（彩虹边缘光、霓虹描边字）整套抄过来，被评“参考过度”。动手前先问清楚要学的是哪个手法。
- **不要用图解解释引擎**：给功能加框、圈、切线、虚线，用户的原话是“不要被本质框死”。要的是观众一眼能感觉到的画面。
- **炫酷不等于光影和 3D**：光晕、镜头光斑、漂浮光斑、拟物玻璃、摄影机 3D 运镜，都被否过。以 2D 为主；卡片自己可以倾斜，摄影机不动。
- **先用文字对齐，再出样张。** 用户说不清具体要什么风格时，文字稿比直接出图省事。第六轮先写了一页文字方案（配色表、三种镜头、每个功能怎么拍、明确不做的清单），确认后出样张，一次通过。
- 用户给出明确的样式描述时（第六轮：浅色纯白配渐变字、深色深色渐变配白字、白板点阵卡、墨迹是主角），照着做，不再自己加东西。

## 已确认的画风（可直接沿用）

| | 亮场 | 暗场 |
|---|---|---|
| 背景 | 纯白 `#FFFFFF` | 近黑 `#08090A`，一角渗进深青绿（呼应网页板面的山林绿） |
| 大字 | 青色横向渐变 `#006A63 → #0FA396 → #4CC6D6` | 纯白，下缘略收灰；落定后可有一道只在字内的掠光 |
| 点阵卡 | 白卡，点 18% 黑，间距和点径按软件白板 | `#131517`，点 18% 白，1px 淡描边 |
| 主墨 / 特征色 | 墨黑 `#15171A` / 青 `#0A9C90` | 白 `#F4F4F2` / 青 `#58FFEC` |

- 每个场景只有三种颜色：底、主墨、特征色。特征色和大字渐变用同一色相。
- 一支片同时用在深色、浅色网页里时，片内按幕交替亮场和暗场，时长大致对半。
- 字体沿用网站字体栈：Segoe UI Variable Display 和鸿蒙黑体，粗体，字很大（中文 200 到 280 号）。
- 点阵卡代表软件的屏幕，有边界、不铺满画面；卡底挂软件真实主栏的原生导出图，画面才不空。
- 明确不做：光晕、光斑、粒子、彩虹或渐变边缘光、霓虹字、噪点、示意框、实体笔、摄影机 3D 运镜、一个场景超过三种颜色。

## 镜头语法

- **幕标题**：每幕开头一张大字。词一个接一个在正中弹出、互相替换，最后排成一行（借用 video-shotcraft 的 `lead-word-zoom-assemble`），或逐词上浮去模糊入场（`blur-slide`）。
- **功能开场**：每幕第一个功能，功能名先在正中排成一行，随卡片升起滑到一侧排成两行，字号不变（借用 `title-demote-to-label`）。
- **同幕后续功能**：侧边大字先换成新功能名，约 0.3 秒后画面才动，字始终领先画面。每个功能因此多出约 0.4 秒演示时间。
- **明暗切换**：一张新主题色的卡从下方升起、放大铺满，成为下一幕的底（借用 `shot-transitions · mask-wipe`）。卡的背景按整幅画面对齐（`backgroundSize` 设为画面尺寸，`backgroundPosition` 设为卡片位置的相反数），铺满时与下一幕的底完全一致，不会跳一下。
- **特写是白板在卡里放大，不是卡片变大。** 卡框（位置、尺寸、倾斜）和卡内视图（白板的缩放与平移）分开控制。特写时卡片右下伸出画面，大字留在卡外的底色上。卡片整张放大铺满全屏时，大字只能压在墨迹上，这个做法已否掉。
- **换功能时平移白板**，换到一块新的空白区域，不清屏，也更像真实的无限白板。
- 借用镜头卡时读卡片说明和 demo 源码，参数从 30fps 换算到 60fps，帧数翻倍；弹簧参数按秒计算，不需要换算。

## 墨迹

### 按软件的链路模拟（`src/s5a/ink/draw3Ink.ts`）

上一版样张里墨迹有拐点和折线感，原因有两个：轨迹是少量控制点连出来的样条，笔宽规则只是近似。现在照软件 Draw3 的源码复刻：

1. **平滑**：Ink Stroke Modeler 的弹簧阻尼位置模型（`spring_mass_constant = 11/32400`、`drag = 72`）。输入按直线插值，每秒输出 360 个点；抬笔时继续迭代追到抬笔点。
2. **笔宽**：按原始输入速度在 1.4 倍到 0.8 倍之间（`smoothstep(速度 / 500)`），经过 60ms 指数低通；每秒最多变 3 倍基准宽度，每像素最多变 0.35。
3. **实时笔锋**：取最近 55ms 走过的弧长，尖端倍率为 `1 − 0.7·smoothstep(弧长 / 4·最大半径)`，沿弧长用 smoothstep 过渡；最后做一遍公切线约束（相邻两点半径差不超过距离的 0.95 倍，正反各扫一次）。
4. **绘制**：画成两端半径不同的胶囊。每点一个圆，相邻两圆之间用精确的外公切线四边形连接；圆和四边形统一成顺时针，放进一条 nonzero 路径。

坐标用“屏幕逻辑像素”，速度阈值因此和软件一致，绘制时再整体缩放到画面上。源码位置：`Draw3.InkPrediction.cpp:236`、`Draw3.StrokeGeometry.cpp:394`（笔锋）、`:525`（笔宽）、`Assets/inkPixelShader.hlsl`。

### 轨迹

- 手的轨迹用连续函数生成，例如画圈的参数方程、三次贝塞尔加进度曲线，或者 `paced()`：弯处慢、直处快，起笔从慢到快，收笔略慢但不停。不要用少量控制点连样条。
- 想要粗细对比（快细慢粗）时，慢段的速度要明显低于 500 逻辑像素每秒，并且持续 0.2 秒以上。笔宽有低通和限速，慢得太短来不及变粗。
- 起笔慢就会有一个圆润的粗头，收笔时笔还在动才留得住笔锋。用户认可的样子参照软件截图：粗墨上一段很长的自然收尖。
- 每笔的实际时长容易超出镜头预算（S 形一开始写了 4.9 秒，镜头只有 1.8 秒）。写完轨迹先量时长：用 esbuild 打包一个小脚本，打印各笔的 `duration`（`media/nh3-remotion/out/tmp/durations.ts` 的做法）。

### 功能怎么表达（用户认可的做法）

| 功能 | 画面 |
|---|---|
| 超低延迟 | 在同一处快速连画几圈，再给特写：几圈依然圆滑，光标贴着墨尖。错开排成一串的圈像奥运五环，已否掉。推近一镜到底接“墨迹预测”，侧边字原地换词，不换边 |
| 墨迹预测 | 光标前面那一小段是特征色。**预测段略微超出光标一点**（约为预测段的最后两成）：光标本来就领先于平滑后的墨，预测是帮墨追上它，不是跑到很前面 |
| 实时笔锋 | 最前端正在收细的那一段（最近 55ms）是特征色，抬笔后退回主墨 |
| 局部刷新 | L1 与 L0 合成一张，高光在这一张上跟着笔尖（这块脏区被重新合成），刚写的一小段墨更亮；L2 不动；不加框 |
| 多层缓冲 | 按软件的 L2（已抬笔）/ L1（这一笔已烘干的前缀）/ L0（笔尖：实时笔锋 + 预测）三层向右上错开；同一条长墨迹三张 → 两张 → 一张（第六版分成“点阵、旧墨、笔尖”，被指出理解错误；爆炸图也被否掉） |
| 手抖修正 | 浅灰的原始输入线在抖，光标跟着抖，墨是顺的。墨要比别的笔细一些，否则把灰线盖住 |
| 边擦边写 | 写满两列的板书上，两支笔同时续写，橡皮同时擦掉另一列的两行，擦完马上在原处写改正的式子 |
| 抬笔修正 | （第七版已删）末端甩出的小钩变成浅灰淡出，换成干净的笔锋 |

- **特征色段用圆头起笔，盖在主墨的圆头上**，分界是一段顺着笔迹的圆弧。用户否掉了硬切的平口分界。

### 第七版补充：先读软件的真实机制，再设计画面

- **“多层画布”指软件的三层墨迹缓存，不是“点阵、旧墨、笔尖”的随意分层。** `Draw3.DrawingController.cpp` 的 `CompositeLayersToBackBuffer(dirty)` 每帧只处理一块脏区：先把 L2（已抬笔的墨迹）拷进这块区域，再把 L1（正在写的这一笔已烘干的前缀）和 L0（笔尖：实时笔锋 + 预测，每帧清空重画）合并盖上。抬笔时整笔并入 L2。片中按这个关系画：三层分开时，L0 用特征色；抬笔后这一笔从 L1 落进 L2；局部刷新时 L1 与 L0 合成一层，笔尖周围亮起一团柔光，L2 不动。第六版凭名字猜成了别的含义，被用户指出“理解错误”。
- 要展示内部架构时，先读仓库 `.trellis/spec/native-desktop/`（如 `draw3-integration.md`、`input-and-ink.md`）和对应源码，再写分镜。
- 分层镜头要让层与层读得开：卡片后仰约 50°，各层沿卡片法线拉开（`Board` 的 `spread`），像爆炸图。卡片只斜十几度时，几层叠在一起读不出来。
- 不要老用 sin x 和正弦曲线。板书用真实的课堂内容（解方程、立方体截面计算），笔画用课堂里常见的动作：连箭头、标坐标、下划线、改错。
- 墨迹内容要符合功能：“边擦边写”是橡皮和两支笔同时工作，擦完马上在原处写改正的式子。

### 第七版补充：手写字与笔宽

- 大量手写字用用户认可的手写字体（Patrick Hand，SIL OFL）。它是轮廓字体，先用 `media/nh3-remotion/scripts/patrick-centerlines.py` 提取中心线（栅格化 → 骨架化 → 剪毛刺 → 按顺滑程度接成笔画 → 平滑），再逐笔走 Draw3 墨迹模拟（`src/s5a/film/handText.ts`）。每个字加确定性的随机变化：大小、倾斜、旋转、基线和字距。
- 字形在小字号下的毛病要逐个看：上标太小像撇号，需要放大；`√` 没有顶部横线，像斜杠，需要补一道；`M` 像 `H`。先出一张字形总览图检查，抽帧时也要再看一遍。
- 一整页板书有几百笔，先把写完的样子预算成一条路径，抽稀并保留一位小数，不要逐帧重算。
- **快细慢粗要慢到约 150 逻辑像素每秒才明显。** 软件的笔宽在原始输入速度 0 到 500 之间从 1.4 倍过渡到 0.8 倍（smoothstep）。速度 380 时只有 0.9 倍，看起来和快段一样粗。
- 速度曲线要先限加速度（v² 每走 ds 最多变 2a·ds，正反各扫一次），再平滑两遍；只做滑动平均时，弯直交界处仍会顿挫。起笔速度给到最高速的四成左右，否则起点是一个过粗的圆头。收笔时笔保持约八成速度离开，笔锋才自然。
- 需要看清笔锋时，用细笔（基准约 18）加放大视图，不要用粗笔（74）。
- **板书小字直接沿字形中心线成墨，粗细恒定，不走 Draw3 的弹簧平滑和实时笔锋**（`handText.ts` 的 `flatStroke`）。原因有三：
  - 弹簧模型让墨迹滞后笔尖约“速度 × 0.024 秒”，一笔只有 0.1 秒的小字会被削圆，`6`、`9` 下面的小圈直接消失；
  - 55ms 的收尖会盖住整笔；
  - 弯处一减速，笔宽就变粗。
  
  用户要的是字体原样（Patrick Hand 的均匀粗细）。长笔画和单独演示的笔画仍然走 Draw3 模拟。
- 根号按数学写法一笔连写：左侧小勾 → 下折 → 上挑 → 顶横，转角做小圆角，横线盖住被开方的数。不要把字体自带的对勾和单独的横线拼在一起。
- 慢段笔宽变粗后，小线圈的内孔会被墨填得只剩一个小椭圆，看起来像脏圈。线圈要够大，内孔直径至少是笔宽的 1.5 倍。

### 第七版第二轮：镜头细节

- 多层缓冲：卡片保持第六版的轻微倾斜，各层向右上错开；后仰成爆炸图反而让人看不出三层之间的关系。层间距要小（每层约右移 47px、上移 39px、纵深 75px），离得太远，观众看不出几层是叠在一起的。整个镜头卡片和视图都不动。整个镜头只写同一条长墨迹，一直不抬笔：先三张，然后 L0 并入 L1 成两张，高光在 L1+L0 这一张上（局部刷新），最后合成一张，高光再跟一段。L2 上放几条之前写好的长墨迹，不放数学题，否则画面杂乱。
- 推近镜头里主栏钉在白板上（`Board` 的 `barRef`），随白板放大并移出画面，特写里就不会出现；换到新画面时再回到卡框上淡入。
- 墨尖和预测末端要按精确时刻在相邻输出点之间插值（`draw3Ink.ts` 的 `pointAt`）。慢放时每帧只前进零点几个输出点，只取离散点会让预测段长度来回跳；光标位置同样要按弧长插值。
- 特写里笔尖附近只留一道墨。和旁边的墨平行挨着时看不清，要换一个时刻，或者换一笔。
- 需要看清预测和笔锋时，局部放慢到约 0.25 倍再恢复，不定格（借用 `speed-ramp-freeze` 的变速）。

## 工程结构（`src/s5a/`）

| 文件 | 作用 |
|---|---|
| `ink/draw3Ink.ts` | 墨迹模拟：原始输入采样 → 弹簧平滑与笔宽（`modelStroke`）→ 某一时刻的样子（`strokeAt`：实时笔锋、预测段、精确时刻插值）→ 胶囊并集路径（`capsulePath`） |
| `film/pace.ts` | 书写节奏：路径 → 240Hz 原始输入（按曲率变速、加速度限幅、平滑） |
| `film/handText.ts`、`film/patrickHand.ts` | 手写字：Patrick Hand 中心线排版、根号合成、匀速成墨、整页静态路径预计算 |
| `film/strokes.ts` | 全片所有笔画（模块加载时建模一次，逐帧只取样） |
| `film/kit.tsx` | 配色、缓动、`Board`（卡框 + SVG viewBox 白板视图 + 分层 + 主栏）、`Ink`、`Cursor` |
| `film/Type.tsx` | 幕标题、副标题、侧边功能名 |
| `film/Acts.tsx`、`film/Film.tsx` | 三幕的镜头逻辑与总装 |
| `film/timeline.ts`、`film/copy.ts` | 唯一的时间表和三语文案 |

每一帧都是纯函数：帧号 → 时间 → 各笔画在该时刻的点列 → SVG 路径。没有状态，也没有随机数（手写抖动用固定种子），任意一帧都能单独渲染，渲染结果确定。

## 实现中的坑

- **带 `transform` 或 `filter` 的子元素不能借父元素的 `background-clip: text`**，会整块消失。渐变字逐字动画时，渐变要写在每个字自己身上，再用 `backgroundSize`（整行宽）和 `backgroundPosition`（该字在行内的偏移）让渐变按整行对齐。
- **用 `delayRender` 在挂载时测量布局的组件，要保证被测元素从第一帧起就挂载**（可以先不显示）。Remotion 每个渲染进程只挂载一次；如果这个进程分到的第一帧还没渲染出被测元素，就永远量不到，那一段会是空白。
- 放大镜头用 SVG 的 `viewBox` 实现，按卡片的布局尺寸栅格化，不要用 `transform: scale` 放大，否则会发虚。
- 光标的画面尺寸随缩放变大，但要比内容放大得慢（按缩放倍数的 0.75 次方），不然特写里光标会大得离谱。点阵的点径同理，按缩放倍数的平方根放大。
- 时间表只写一份（`src/s5a/film/timeline.ts`），镜头、字幕、转场都从它取帧号。合成的总帧数也从这里取（`Root.tsx` 引用 `DURATION`）。
- **同一个词分两个阶段显示时（单词放大、整行排列），两个阶段要用同一套行盒和字号**，放大用 `scale` 绕基线做。直接把字号翻倍会改变行盒，基线就对不上（`HLSL` 接棒时曾跳高约 75px）。
- 逐字渐变的背景宽度是估算的行宽，实际字形可能更宽。设成 `backgroundRepeat: no-repeat`，再用 `backgroundColor` 填渐变末端色，否则超出部分会从渐变起点重新平铺（`FPS` 的 S 右下角曾因此发暗）。
- 三幕片子的明暗交替里，一定有一处接缝两边同色（这次是第三幕暗场接第一幕暗场）。这里不再升一张同色的卡，改为卡片沉回画面下方，留下空场接回开头。

## 流程

- 预览给用户时只启动 Remotion Studio（`.claude/launch.json` 的 `remotion-studio`），不需要渲染整片。用户在 Studio 里判断动起来的感觉。
- 自检用 `still` 抽单帧（可以加 `--scale=0.5` 提速），或抽几帧拼成总览图。每次改完先自己看过关键帧再交给用户。
- 样张只能确认静态画风，节奏和动感要看 Studio。
- 用户验收后不马上渲染成片：等官网其余视频都完成后统一渲染、嵌入（2026-11-23 用户要求）。
