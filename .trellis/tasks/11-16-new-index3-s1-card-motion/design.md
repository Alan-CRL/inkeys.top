- 点击和换场绑在一起：指针点下去的那一帧，按钮变化、墨迹淡出、内容切换同时开始，像“在动作上剪切”。

### 指针（用户 2026-11-16 指定）

最初的方案是不放任何光标。预览后发现视线停在墨迹上，主栏在下方自己变化，没有东西把视线带过去，观众不知道发生了什么。所以加入指针，由它串起整个循环：写 → 去主栏点按钮 → 到下一处 → 写。

- **在画布上**是软件自己的“画笔指针（高亮）”：笔尖在左上角的五边形小笔，半透明地填着当前笔色，带浅色描边。荧光笔时是它的矩形笔尖光标。书写时指针的笔尖就是墨迹的最前端。
- **在主栏上**是鼠标箭头。越过主栏顶边前后约 12 的范围内两种光标交叉过渡。
- **移动要灵动**：走一条略弯的弧线，起步快、收得慢，到位前有很小的过冲。
- **点击有效果**：箭头向笔尖方向压一下；按钮缩到 88–90% 再略微回弹；松开的瞬间从按钮中心扩出一圈青绿色水波。笔按钮换内容按软件真实的动画：旧内容缩小淡出，中点换图，新内容放大淡入。
- 画笔光标的样子是按源码调查里的描述画的（五边形的顶点、50% 填充、浅色描边），没有和软件的实际像素比对过，需要用户确认；必要时改为原生导出。
- 简化：真实软件里要先展开笔的属性面板才能选荧光笔，这里演成点一下笔按钮就切换。用户知情。
- 不演给观众看的状态复位（Highlight 变回 Soft Pen、取消定格）都安排在该按钮滑出卡片之后。
- 不做：粒子、发光、扫光、镜头推拉、被圈对象的反应。

### 笔迹路线的要求（R11）

样张里的圈是用公式生成的，收笔向上挑，用户指出不自然。成品里：

- 圈从右上方起笔，逆时针一圈，收笔时顺着圆的走向越过起点一小段，自然重叠，不向外甩。
- “越过边框”靠圈本身比屏幕大来实现，不靠额外的尾巴。
- 路线用手工编排的采样点（带时间），转弯处减速、长弧处加速，抬笔时笔还在动（这样笔锋才会留下）。
- 荧光笔的路线接近水平，带很小的起伏，速度大致均匀。

## 5. 墨迹的画法

用户选择“混合”：墨迹不走原生导出，在 Remotion 里按软件的规则画。规则来自 `research/codex-ui-survey-result.md` 第 4 节（源码 `Draw3.StrokeGeometry.cpp`、`Draw3.InkPrediction.cpp`）。

### 软笔

记基准直径为 `B`，“预期速度”为 `E`。

1. 粗细随速度：`u = clamp(speed / E, 0, 1)`，`s = u²(3−2u)`，目标直径 `= lerp(1.4B, 0.8B, s)`。慢则粗，快则细。
2. 目标直径经过 60ms 时间常数的低通（每个采样的系数限制在 0.02–0.35）；半径变化每秒最多 `1.5B`、每像素最多 0.35。
3. **起笔没有渐粗**：先保持基准粗细，再跟随速度。
4. **实时笔锋**：笔迹最前端最近 55ms 走过的那一段沿弧长收细，尖端比例 `= 1 − 0.7 × smoothstep(这段的长度 / (4 × 半径))`，最低到 30%。写得越快，这段越长，笔锋越明显；笔停住不动，这段缩短，笔锋消失。
5. 抬笔后的成品笔迹保留同一套笔锋。

视频里每一帧都按“写到此刻为止的采样点”重新计算整条笔迹，所以书写过程中笔锋一直跟在最前端，这就是要给用户审阅的效果。

取值（1 倍坐标）：`B = 5.2`，`E = 1090`（随书写时长调整，保持平均速度约为 `E` 的 0.7 倍）。软件里是 3 单位粗细配 500 像素每秒；这里先按同一比例放大（让笔锋在小卡片里看得清），书写加快后又把 `E` 同比例调高，保住转弯粗、长弧细的变化。这是为了可读性做的调整，记入来源说明。

### 荧光笔

竖直的方头笔尖横扫，等宽，不做笔锋；一笔之内重叠不加深。带高约 21（1 倍坐标），两端是竖直的平边。起止贴着被标记的文字，不画到屏幕外面（最初让它从屏幕外扫进来，用户指出和内容不贴合）。

### 四项检查（R12）

| 问题 | 怎样避免 | 怎样核对 |
| --- | --- | --- |
| 路径错位 | 笔迹的采样点和示例内容用同一套 1 倍坐标；内容的位置写成常量，笔迹从这些常量算出目标框，不各写各的数字 | 每道笔迹落定后抽帧，叠上目标框检查：圈要完整包住标题或行星，荧光笔的带子要盖住那句话的字高 |
| 笔锋不正常 | 每帧按当前时刻重算整条笔迹；抬笔时笔还在动 | 书写过程中每隔几帧抽一帧放大看最前端；和原生终帧叠图比对 |
| 颜色不合适 | 软笔 `#FF1000`、荧光笔 `#FFC510` 35%，都是软件调色板里的颜色 | 浅色、深色两版分别看：红色在白色网页、深色视频上都清楚；黄色荧光笔下的文字仍能读，深色版里偏暗时换用更亮的底或调整纸张颜色，不改荧光笔的不透明度 |
| 匀速书写 | 采样点带时间：起笔稍慢，长弧加速，转弯减速，收笔前略慢但不停 | 画出速度曲线；最快和最慢的速度至少相差一倍，粗细变化肉眼可见 |

### 核对

- 用现有的 `media/inkeys3-hero/native/HeroInk.inc`（真实笔迹模型，输出终帧）导出同一组采样点的终帧，和 Remotion 里画出的终帧叠在一起比对粗细和笔锋。
- 先出一段只有墨迹的放大测试片给用户审阅；不通过则按用户意见调整，或改用硬笔（等宽，无笔锋）。

## 7. Remotion 工程

```

    ink/highlighter.ts
    ink/render.tsx          把带半径的点画成笔迹
```

- 渲染必须确定性：不用 `Date.now()`、`Math.random()`。
- 本机是 Windows ARM64，Remotion 的合成器只有 x64 版本，需要用便携的 x64 Node 运行（旧工程 `scripts/run.mjs`、`setup-runtime.ps1` 的做法可以照搬）。这一条来自旧工程的记录，开工时先复核。

### 窄屏的比例（R13）

视频的结构决定了哪些地方可以裁：

- 顶部约 28%（墨迹最高点以上）是纯底色，可以裁掉或被文字占用。
- 左右两侧不能裁：左边是屏幕的左沿和越出去的墨迹，右边是主栏。
- 所以视频一律按宽度铺满、贴底对齐（`object-fit: cover; object-position: 50% 100%`），容器不能比 2:3 更瘦高。

文字是固定字号，卡片越窄，文字占的比例越大。按现有样式推算：卡片宽 290 以上时，三种语言的文字都在墨迹最高点之上；现有样式在视口 821–1000 之间会把卡片缩到 230–290 宽，英文会折成三行，压到画面上。

接入时的做法：

| 视口宽度 | 排法 | 卡片 |
| --- | --- | --- |
| 1000 及以上 | 三张并排 | 固定 2:3（去掉现在的 `min-height`），宽 290–384 |
| 600–999 | 一行横向滑动，带吸附，露出下一张的一部分 | 固定宽约 320，2:3 |
| 600 以下 | 竖排，每张占满一行 | 2:3（390 宽的手机上约 350×525） |

600–999 的排法是建议，接入时做出来给用户看，用户不喜欢横向滑动就改成竖排并限制卡片最大宽度。验收时除了 1440、1024、768、390，再加 1000、999、820、600、599、320 这几个断点附近的宽度。

## 9. 参考的镜头语法

本片是单镜头用法，不套完整宣传片的流程，不配声音。借用的镜头卡（实现前读卡全文和对应 demo 源码）：

| 用在 | 镜头卡 | 借用什么 |
| --- | --- | --- |
| 圈画 | `draw-svg-trace` | 笔头领先、一个主体一次闭合、画完后停留 |
| 内容切换 | `blur-slide` | 位移、模糊、透明度共用一条进度 |
| 第三拍 | `speed-ramp-freeze`（freeze-annotate） | 流动 → 定格 → 圈注 的顺序 |

墨迹本身不用镜头卡里的描边写法（`strokeDashoffset` 等宽描边），因为要体现软件的速度粗细和实时笔锋，按第 5 节新写。

## 10. 风险

| 风险 | 应对 |
| --- | --- |
| 软笔笔锋达不到“和软件一样” | 先做墨迹测试片单独审阅；用原生终帧比对；退路是硬笔 |
| 当前 `dev` 上导出适配编译不过 | 让 Codex 先只读核对并给出补丁，自己构建；仍不行则在 Remotion 里按 Codex 查到的取值仿制主栏（需用户同意，因为偏离了“混合”的决定） |
| 三张卡片同时播放时太吵 | 这一张做完后放进网页看整体；必要时错开三张的起始时间 |
| 视频底色与卡片底色有色差 | 视频铺满整张卡片，没有接缝；编码后抽帧核对底色 |
| 主栏文字在 1 倍屏上偏小（约 10px） | 样张里可读；成片后在 1 倍、2 倍屏各看一次，必要时把主栏放大到只露四个按钮 |
