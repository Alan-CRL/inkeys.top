# 静态资源多地址 CDN 与本地自动回退

## Goal

`docs/.vuepress/public/` 下的图片、GIF、`.uink` 等资源默认从本站（inkeys.top）加载；某个文件加载失败，或者当前通道卡住而其他通道正常时，自动换到 123 云盘直链（先 `.cn`，再 `.com`，以后可追加 S3）。

## Background

- Plume 的 `replaceAssets` 来自 `@vuepress/plugin-replace-assets`，只在构建时把路径换成单一地址，没有回退，也不支持多个地址；上游截至 rc.219 / plugin rc.137 没有相关能力。
- 2026-11-24 核对：public 的 79 个文件与 `.com` 下逐个哈希一致；`.cn` 同路径可用；两者都返回 `Access-Control-Allow-Origin: *`，不存在的文件返回 403；没有 `Timing-Allow-Origin`。
- 两个 123 域名在测试机上速度几乎相同（同为 `X-MF-CDN`），因此不做“选最快”，只防卡死。

## Requirements

- 默认顺序：本站 → 123 `.cn` → 123 `.com`。远程地址列表只维护一处，追加地址只需一行（目录结构与 public 相同）。
- 构建不改写任何资源路径，HTML 和组件默认使用本站路径；开发模式不注入运行时。
- 单个文件加载失败（404/403/连接失败）：只让这个 `<img>` 依次换到尚未试过的下一个地址。
- 卡顿看门狗：页面上可见区域附近的 public 资源（`<img>` 与组件内联样式带出的 CSS 背景）超过 6 秒仍未加载完，就测一次所有地址：
  - 当前通道探测失败，或有通道耗时不到它的一半：按默认顺序整站切到其中最靠前的通道（不按测速挑最快），已在页面上的资源、之后渲染的内容和组件背景都跟着切换，卡住的资源重新加载。
  - 当前通道响应正常（探测 2 秒内完成）却仍有文件卡住：只让该图片单独换到下一个地址。
  - 所有通道都慢：不切换（用户自身网络慢，切换只会让下载从头开始）。
- 切换结果只在本次浏览会话内记住。
- 只处理 public 中真实存在的文件；页面链接、外部图片、打包的 JS/CSS 不受影响。

## Out of Scope

- 按地区或测速自动选最快的通道。
- S5-A 的 HLS 视频（转码路径，不在 public 内）。
- 打包后的 JS/CSS chunk 走 CDN。

## Acceptance Criteria

- [ ] `pnpm docs:build` 通过，构建产物中不含 public 资源的 CDN 地址。
- [ ] 正常情况下 public 资源全部来自本站，不请求 CDN。
- [ ] 本站上某个文件返回 404 时，该图片改从 `.cn` 加载，其余仍走本站。
- [ ] 本站通道变慢（探测明显慢于 `.cn`）且有资源卡住时，整站切到 `.cn`：图片、CSS 背景、下载链接（含 SPA 切页后的新内容）都使用 `.cn`。
- [ ] 本站探测正常但某个文件卡住时，只有该文件改走 `.cn`，其他资源不变。
- [ ] 无页面脚本错误。
