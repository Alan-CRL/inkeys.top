## 0. 总体思路

### 0.1 页面要回答的三个问题（按顺序）

1. **这是什么？** 首屏下方第一屏就要一句话说清楚：Windows 上的开源免费屏幕批注软件，可以在任何画面上书写，也能当白板用、配合 PPT 放映。
2. **对我有什么用？** 用具体场景回答，访客在场景里认出自己的情况，不需要点名人群。**亮点藏在场景里讲**：讲“画面停在哪里就写在哪里”时顺带展示软笔笔锋和定格；讲“站上讲台”时顺带展示手掌橡皮和大号底栏。不把亮点单独拉出来罗列。
3. **怎么开始？** 场景讲完，页面在情绪最高的时候给出下载。下载入口共两处：首屏和场景之后的 S6。

技术细节，例如手抖修正、实时笔锋、墨迹预测、压感、各种橡皮的原理，**不在主页展开**。以后会单独做一个功能介绍页面，入口放在顶栏和主页的功能卡片上（见 S8）。

### 0.2 叙事主线

```
首屏：艺术字书写＋两侧少量场景碎片＋立即下载 / 为 GitHub 点亮 Star
  └ S1 它能做什么：一句话＋三张能力卡片（不放下载）
      └ S2 场景  从屏幕到讲台：三张平铺卡片
                 （屏幕演示 / 会议与演讲 / 教室与白板）
      └ S5 场景④  A 书写体验（高亮纯色区块＋Remotion 演示）／B 界面与设备（背景图＋设置界面＋主栏）
  └ S6 再次下载（标题＋副标题＋立即下载＋系统要求）
  └ S7 画廊（三张原生大图）
  └ S8 功能卡片（通往功能介绍页）
  └ S9 开源、免费，也足够可靠（Star、项目规模、稳定性）＋常见问题
```

S2 用三张卡片覆盖三类场景：屏幕演示（桌面批注）、会议室与演讲（PPT）、教室与白板。S5 对应草案里“极致性能的画布、画笔效果的特写、兼容各种设备”，作为叙事的高潮和收尾，用画面和感受来讲，不列技术条目。这条线和宣传片脚本同源，以后做宣传片可以直接按同样的顺序分镜。

### 0.3 媒体策略

| 区域 | 媒体类型 | 原因 |
| --- | --- | --- |
| S1 | 三张竖向纯色卡片，每张下方是一段 Remotion 制作的小尺寸轮播，无文字，和卡片融为一体 | 快速认识三种用法，不需要细节 |
| S2 | **三张平铺卡片**：卡片内一侧网页文字，另一侧短循环画面（无文字），从上到下排列 | 画面不必很大，文字说明更充分，也方便 i18n |
| S5 | A：Remotion 书写演示（内容后续定）；B：深浅色都适用的背景图＋原生设置界面（背景模糊）＋主栏 | 笔锋需要真实像素；界面放在真实背景上才能体现质感 |
| S7 | 现有原生合成大图，静态 | 已经制作完成，质量高，适合放大细看 |

画面里的主栏、笔迹和图形都来自原生采集。不做网页模拟的书写（网页无法体现桌面程序的性能，反而削弱亮点）。

**为 i18n 准备的媒体约束**
- Remotion 等渲染出来的视频和动图里，默认**不放说明功能的文字**，说明文字用网页文字叠加，切换语言时只改网页。
- 画面里的背景内容（网页正文、PDF、幻灯片、白板上的字）可以有文字，统一用**英文**，所有语言共用一套素材。
- 原生主栏按现有素材规范用 en-US 界面采集。如果某个场景需要随语言变化的主栏，就把主栏做成单独的图层，按语言替换。
- 版式留足空白，每屏的文字尽量少，给其他语言更长的译文留出空间。

### 0.4 交互、版式与文案原则

- **不使用滚动进度驱动动画。** 鼠标滚轮无法平滑滚动，滚动推进的动画会一顿一顿，效果难看。全页改为：
  - 进入视口后**按时间自动播放**，离开视口暂停；
  - 多步骤的演示做成**步骤卡**（参考 Xmind）：当前步骤有进度条，可以点击任意步骤直接切换，提供暂停按钮；
  - 页面滚动保持浏览器原生行为，不吸附、不劫持滚轮。
- **整体风格方向。** 纯色背景、前沿的简洁风格，参考 Xmind、OpenAI、Anthropic 的官网。首屏可以稍微丰富一些，其余区块保持简洁、留白充足。
- **下载按钮统一写“立即下载”。** 不在按钮上强调“免费”：以后会在 Microsoft Store 上架付费版本供用户赞助，GitHub 版本继续免费下载。正文和 FAQ 仍可以说“开源免费”。
- **媒体不局限于方框。** 图片和演示可以超出栏宽、溢出到页面边缘、与相邻区块叠压，和网页融为一体。本稿只在各场景里标出“适合破框”的位置，具体样式后续再设计。
- **装饰性墨迹要克制。** 手写元素只在控件上点缀，例如按钮下的一道手写下划线、标题旁的一个圈注，要恰到好处。不做大面积的背景墨迹（之前的背景墨迹装饰参与感低、也不好看，已经弃用）。
- **文案面向新用户。**
  - 不堆底层术语（RTS、ROT、COM、HLSL、dev 分支、脏区等）。
  - 不解释显而易见的事，不写操作说明书式的文字。
  - 不写“未来实现”“尚未支持”之类的话：官网和软件同期上线，上线时功能就已经发布。唯一例外是你指定的 S2 卡片 3 角注（自动恢复笔记）。
  - 可以适度使用大众听说过、能带来质感的专业词，例如“C++”“Direct3D”“GPU 加速”。
- **品牌名称。** 简体中文页面里品牌写作“智绘教Inkeys”；其他语言一律写“Inkeys”。从 Inkeys3 开始统一叫 Inkeys，“智绘教”只是为了让老用户找得到我们的过渡。
- **术语的本地化。** 中文可以直接说“PPT”；其他语言按习惯译成 slides / slideshow 等，在 l10n 时处理。
- **页面保持纯净。** 不加小标签、徽章等额外元素，内容宁少勿多。
- **首屏和介绍横幅保持干净。** 不堆用户数、Star 数这类数字；Star 和项目规模放到 S9 介绍开源时顺带展示。

## 2. 逐场景设计

### S0 首屏

**目的**：建立品牌印象；同时让还没往下滚的访客，也能大概知道 Inkeys 是做什么的。首屏是全页唯一“不那么简洁”的地方，但碎片只是为了吸引用户而适当加入的特色，不能打扰中间的内容。

**背景与布局**
- 一大片干净的纯色背景，中央是 Inkeys 艺术字书写，这是首屏的绝对主角，周围留足空位。
- 艺术字下方是标语和两个按钮。
- 左右两侧少量放置场景碎片（共 5 张，不要像 Xmind 那样多），右侧的部分碎片可以伸出屏幕边缘。碎片位于艺术字区域之外，不与标语和按钮重叠。
- 书写样式面板和暂停按钮挪到不显眼的位置，例如只在鼠标悬停于中间动画时才出现（具体位置在样式阶段定）。
- 窄屏：隐藏碎片。

**文案草稿**
- 标语：`让屏幕上的书写行云流水，让每一次操作都赏心悦目。`（保留）
- 主按钮：`立即下载`
- 次按钮：`为 GitHub 点亮 Star`

**场景碎片**
- 每张碎片都是**专门为“露出一角”设计的示意图**，不是从下方媒体里裁切出来的。内容合适、展示合适才放，不随意凑角。
- 平时：静态，半透明，安静，不会自己闪动或强调。
- 悬停：变成不透明并略微放大；同时出现一条手写风格的细线指向碎片，旁边是手写样式的名称。后续可以考虑用网页实时渲染这条墨迹，但手写字形需要单独设计和把关。
- 点击：跳到下方对应的场景（交互细节留到下一轮）。

| 位置 | 碎片内容 | 悬停名称 |
| --- | --- | --- |
| 左上 | 英文网页的一角，一句话被红色软笔圈出，旁边一个箭头 | 屏幕批注 |
| 左下 | 一段悬浮主栏，软笔处于选中状态，带一点光影 | 主栏 |
| 右上（伸出屏幕） | 点阵白板的一角，一条函数曲线和一个立体图形 | 自由白板 |
| 右下（伸出屏幕） | 幻灯片的一角，标题被圈出，边上露出翻页按钮 | PPT 演示 |
| 左侧中部或右侧中部 | 几道不同笔型的笔触（软笔笔锋、荧光笔） | 多样笔触 |

碎片里的背景文字用英文，悬停名称是网页文字，可以随语言切换。

### S1 介绍横幅：它能做什么

**目的**：替代现在的巨型彩虹墨迹转场（彩虹墨迹整体去掉）。只回答“这是什么、能做什么”，把三项核心能力列出来。不放下载按钮，下一次出现下载就是 S6，让访客看完内容后自然想点。

**背景与布局**
- 背景延续首屏的纯色，不加装饰。
- 分成两个层次，中间留出大片空白，不挤在同一屏：
  1. **标题段**：大标题和一句话居中，上下留足空白，单独占据视线。
  2. **三张卡片**：继续往下滚，一屏内能完整看到三张卡片。
- 三张卡片从左到右并排，都是**竖向**的长卡片。每张卡片用纯色填充（三张各用一种柔和的颜色，或三张统一颜色，样式阶段再定）。
- 卡片结构：上方是标题和一句说明；下方是一段小尺寸的内容轮播，后期用 Remotion 专门制作，画面要和卡片融为一体（铺到卡片边缘，不加内框），看不出是嵌入的视频。
- 点击卡片跳到 S2 中对应的卡片（屏幕批注 → 卡片 1，PPT 演示 → 卡片 2，自由白板 → 卡片 3）。
- 窄屏：三张卡片竖排，或改成横向滑动。

**文案草稿**
- 大标题：**在屏幕上随时书写、标注与讲解。**
- 一句话：`桌面批注、自由白板、PPT 演示，一个软件就够了。`
- 三张卡片（可以和后面场景的文字不同，后面是更深入的介绍）：
  - **屏幕批注**：`在任何画面上直接书写。`
  - **自由白板**：`推导与板书，空间足够。`
  - **PPT 演示**：`放映时自动跟上，边讲边写。`

**媒体设计**（每张卡片一段小尺寸轮播，Remotion 制作；无说明文字，背景内容用英文）
1. 屏幕批注：英文网页上一句话被软笔圈出 → PDF 上荧光笔扫过一行 → 视频定格后圈出画面里的物体。
2. 自由白板：点阵白板上写出算式 → 画出函数曲线 → 放上一个立体图形，翻到下一页。
3. PPT 演示：幻灯片标题被圈出 → 翻到下一页画箭头 → 翻回第一页，之前的圈仍在。

三张卡片的轮播进入视口后自动播放，离开视口时暂停；系统开启“减少动态效果”时只显示静态画面。

### S2 场景：从屏幕到讲台（合并原 S2–S4，三张卡片）

**目的**：用三张卡片覆盖三类使用场景。每张卡片的标语先抓住用户的需求，再用说明和画面展示这个场景里的亮点，不罗列基础功能。

| 卡片 | 场景 | 对应的核心能力 |
| --- | --- | --- |
| 1 | 屏幕演示 | 桌面批注 |
| 2 | 会议与演讲 | PPT 演示 |
| 3 | 教室与白板 | 白板＋教学工具 |

**背景与布局**
- 上方是本节的大标题和一句说明。

### 4.2 本方案采用的做法

1. **首屏下方第一句话说清能做什么**（Epic Pen）：S1 的大标题直接说清动作，三张卡片列出三项核心能力。
2. **下载按钮旁写一行系统要求**（Raycast、ClassIsland、Xmind）：S6 的按钮下方写“支持 Windows 7 SP1 及以上”；不写版本号。
3. **步骤卡自动轮播，不靠滚动驱动**（Xmind）：用于 S2–S4；小标题学习它的对仗短句。
4. **页尾呼应首屏**（Raycast、希沃）：S6 和首屏一样直接放在背景上，不用卡片。
5. **亮点融进场景，而不是单列特写**：这是你的要求，也和 ClassIsland“每条功能都用教学场景来解释”的做法一致。
6. **开源社区的信任信号放在页尾**（ClassIsland 的“社区认可”）：S9 展示 Star 数和项目规模，不放到首屏。
7. **画廊按场景分组**（Goodnotes 的 Tab）：图片多起来以后再分组，目前只有三张，按顺序排列。
8. **不采用**：首屏放空画布（只适合网页应用）；网页模拟书写；只放图标卡片不放产品画面；下载前设置等待或长段警告；主页放性能数字。
