# UInk 1.1 规范设计

> 状态：规划讨论中（2026-11-24）。本文只记录需求、约束与验收；具体字段设计放 `design.md`，待决策确认后再写。

## Goal

在 UInk 1.0 Beta（`Header.version = 10`）的基础上设计 UInk 1.1：

1. 让规范更易被人类与 Agent 理解：重写文档语言，补充可视化图示，重做 UInk 主页。
2. 吸收 Inkeys（Draw3）与 ICC-CE 的真实需求，补充或调整格式能力。
3. 引入**功能分级**：各板块分为核心 / 标准 / 完整三级，另有可与任一级并存的 Inkeys 附加级；高级兼容低级，并在文档中引导实现者做回退处理。

## 用户已定的方向

### 功能分级

- **核心级（Core）**：所有声称支持 UInk 读写的软件都必须支持；保证跨软件正确或大致正确地通用。大部分支持多页与矢量的软件都应能做到。
- **标准级（Standard）**：覆盖 ICC-CE、Inkeys 这类软件的大部分场景（多页等），引入部分高级能力，但不需要额外的特殊适配。
- **完整级（Full）**：全量功能，例如多图层、HDR 颜色等普通软件用不到的能力。
- **Inkeys 附加级**：可与任一级并存，服务 Inkeys 特有的 Clear 与高级橡皮。
- 兼容方向：高级兼容低级，有 Inkeys 附加级的兼容没有的。反方向不保证完整兼容，但核心功能必须能正常工作（例如 ICC-CE 读取含 Inkeys 高级橡皮的文件时，橡皮可以完全失效）。
- Inkeys 可以略微牺牲高级橡皮，导出兼容的 UInk 文件；文档需引导实现者考虑兼容回退。

### 版本兼容

- 1.1 尽量兼容 1.0，允许破坏性修改。
- 最好让 1.0 读取器读取 1.1 文件时，能读出其中兼容的部分。
- 最好让 1.1 读取器能读取 1.0 文件；改动太大时可以不支持。

### 文档与主页

- 大幅优化网站描述，完善文档；规范语言对人类和 Agent 都易懂。
- 在 Shape、Ink 等处加入可视化描述，帮助适配。
- 重新制作主页，让 UInk 更有吸引力。

### 决策方式

- 细节决策由 AI 给出推荐方案，用户确认后再定。

## Inkeys 已提出的格式需求（摘要）

| 编号 | 需求 |
| --- | --- |
| R1 | 一个逻辑文件 = 多个页（画布），桌面、PPT、白板共用 |
| R2 | 按页追加：同一页的新版本作为完整块追加到末尾，以最后出现的为准；导出时整文件重写为有序紧凑文件；需衔接实时写入与崩溃恢复 |
| R3 | 页面元数据官方化：页码；PPT 的 SlideID、绑定方式、页状态（活动 / 保留）、页类型（普通 / 结束页）；白板背景颜色与图案；预留图层等扩展 |
| R4 | 白板只靠官方 `workspaceType` 识别；PPT 页码绑定改为 PPT 类型 + 绑定方式字段 |
| R5 | 页内容是 Stroke / Shape / Clear 的有序日志，Clear 正式化；Inkeys 每页最多一个 Clear |
| R6 | 不保存重做与编辑历史，保留 `undoId` 分组 |
| R7 | 不要求完整性校验 |
| R8 | 每笔笔尖描述：形状、宽高比、方向、宽度值含义；表达荧光笔与矩形 / 方形橡皮 |
| R9 | 墨迹与图形描边的 `lineCap` / `lineJoin`；零长度 dash 依赖圆帽 |
| R10 | 坐标单位需明确（记录 DPI 缩放或统一单位） |
| R11 | 标准 Shape 层基本不变，复杂图形写成一组 Line / Polyline；补写 dash 单位、闭合虚线拆分、多项共享 `undoId` |
| R12 | 图形对象元数据官方化（首项存 id、revision、preset、construction、style、aux、transform、partCount，后续项只存引用） |
| R13 | 未知键忽略；元数据无法识别时退回标准层，不拒绝整页 |

## ICC-CE 需求（摘要，详见 `research/icc-ce-uink-gaps.md`）

ICC-CE 已有 UInk 1.0 读写实现（`Ink Canvas/UInk/`），但只是部分适配；它是“低等级读取器”的真实样本。

| 编号 | 发现 | 已抽查 |
| --- | --- | --- |
| I1 | 读取器没有 Clear 分支，Clear 当未知块跳过 → 清空前的旧内容重新显示 | ✅ `UInkReader.cs` |
| I2 | Erase Ink 被转成可见笔画 | — |
| I3 | 笔迹统一写 Pen；荧光笔、椭圆 / 矩形笔尖、宽高、压感开关塞在私有 `extra["icc:da"]`；压感只能从宽度反推 | ✅ `UInkConversion.cs` |
| I4 | 保存时所有内容 `undoId = 0`；`contentId` 跨页连续计数（违反 1.0 每个 Canvas 从 0 开始） | ✅ `UInkIccMapper.cs` |
| I5 | 图形导出为 Ink，导入的 Shape 变成轮廓笔画；坐标轴、圆锥曲线、立体等复合图形由多条笔画组成，没有可编辑的组合对象或曲线路径 | — |

| I9 | Media：只还原平移，丢失仿射、拉伸方式、透明度；建议增加 `fit` / 裁剪 | — |
| I10 | 插件页状态没有标准承载方式；建议 Full 级的命名空间扩展封套 | — |
| I11 | 读取器类型容错过宽（float→int、int 当 bool、重复键未拒绝），需要字节级反例样例 | — |

## 已确认的决策

### 第一轮（2026-11-24）

| # | 问题 | 决定 |
| --- | --- | --- |
| D1 | 版本号与 1.0 兼容 | `Header.version = 11`；定义 version = 主版本×10 + 次版本，同主版本读取器遇到更高次版本时尽力读取（跳过未知块 / 键）。给 1.0 Beta 发勘误，使更新后的 1.0 读取器能读 11；1.1 读取器必须能读 10。 |
| D2 | 等级是否写进文件 | **不声明**。等级只是给读取器 / 写入器实现者的对接参考，文件内容自由、功能可自由组合；需要跨软件互动时，实现需通过对应等级的读取与写入认证。读取器按内容自行推断。 |
| D3 | Clear 的等级 | **Clear 整体归 Inkeys 附加级**。文档需为未实现 Inkeys 级的读取器给出回退建议，并引导写入器兼容导出时去掉 Clear 及其之前的内容。 |
| D4 | 按页追加 | **读取进核心级，写入可选**：所有读取器都实现“同一页以最后出现的版本为准”；写入器可选择是否按页追加，导出 / 整理时重写为紧凑有序文件；页面目录靠顺序扫描，不加文件尾索引。 |

### 第二轮（2026-11-24）

| # | 问题 | 决定 |
| --- | --- | --- |
| D5 | 高级橡皮 | 整个 Erase Ink（`inkType = 0`）及橡皮笔尖形状归 Inkeys 附加级。未实现该级的读取器必须跳过 Erase Ink（橡皮失效），不得画成普通笔；兼容导出时把擦除烘焙进笔画几何。 |
| D6 | 图形元数据 | 分层：图形对象层（objectId、revision、partIndex / partCount、preset、transform）进标准级；预设注册表与 construction 参数进完整级；不认识的一律退回标准 Shape 层。 |
| D7 | 核心级范围 | **核心级必须很小**：墨迹（宽度变化 + 颜色；可以不支持透明度；端帽默认圆头）、多页、基础图形。Media 不进核心级。如果等级不够用，可以再加一级。 |
| D8 | ICC-CE 建议的新能力 | **纳入** Media 裁剪与适配（`fit` / `crop`）。**不纳入** Path 曲线（用折线表达，最多作为扩展）、点级压感（UInk 以 `width` 正确显示为准）、Text 文本块。 |
| D9 | 撤回模型 | 保持 1.0 模型（`undoId` 分组，不存重做与编辑历史），不引入对象事务。 |

### 第三轮（2026-11-24）

| # | 问题 | 决定 |
| --- | --- | --- |
| D10 | 等级数量 | **加一个基础级**：核心级 → 基础级 → 标准级 → 完整级，外加 Inkeys 附加级。基础级只含外观类能力（透明度、荧光笔、笔尖、端帽、虚线、箭头、圆角、页面背景），不含 Media 与 PPT。 |
| D11 | `renderOnlyWhenLatest` | 保留，降到完整级；低等级读取器忽略它。 |
| D12 | 页面元数据位置 | 放在 Canvas，以第 0 层为准（与 `viewport` 规则相同）。 |
| D13 | 坐标单位 | **Canvas 坐标使用 Device 像素（物理像素），不记录 DPI 缩放**。缩放由 `Canvas.viewport.scale` 表达，渲染器按视口缩放渲染。需改写 1.0 中“平台无关逻辑像素”的定义。 |
