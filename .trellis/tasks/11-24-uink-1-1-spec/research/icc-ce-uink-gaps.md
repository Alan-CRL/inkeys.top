## Summary

This is a read-only source review against the supplied **current UInk 1.0 Beta, version 10**. In the citations, `U/`, `M/`, and `H/` stand for `Ink Canvas/UInk/`, `Ink Canvas/MainWindow_cs/`, and `Ink Canvas/Helpers/`. `spec/` stands for `website/docs/standard/`. Line ranges are inclusive.

- **Multi-page ink already fits UInk 1.0.** ICC writes a Canvas for every whiteboard page, including empty ones. Its adapter regenerates page IDs, opens at page 1, and only exports media from the active page. Basic ordered pages and stable page IDs belong in **Core**. `M/MW_UInk.cs:67–98,297–318`; `spec/blocks/canvas.md:65–75,113`
- **A single point width preserves only part of a WPF brush.** ICC stores brush settings in `extra["icc:da"]`, then overwrites the recovered width and height and reconstructs pressure from visible widths. A portable nib model and optional pressure samples belong in **Standard**. `U/UInkConversion.cs:27–56,83–119,252–299`
- **Ordinary shapes and media expose adapter gaps.** UInk 1.0 already supports dashes, open-arrow markers, filled shapes, affine media, and PDF page state. ICC exports drawn shapes as Ink, imports Shape as an outline, and maps media placement to translation. `M/MW_ShapeDrawing.cs:1279–1349,2596–2619`; `U/UInkIccMapper.cs:104–125`; `U/UInkConversion.cs:124–154`; `M/MW_UInk.cs:138–159,372–423`
- **Compound classroom diagrams, page presentation, and editable scene content need portable structures.** ICC builds diagrams such as axes, conics, and solids from multiple strokes, has a configurable board background, and can persist editable SVG scene JSON in its native element sidecar. Prioritize page background and grouped vector paths. `M/MW_ShapeDrawing.cs:114–139,2096–2175`; `M/MW_BoardIcons.cs:244–257`; `M/MW_Save&OpenStrokes.cs:138–172,872–876`
- **ICC’s undo model can replace arbitrary objects.** TimeMachine records originals and replacements, geometry and style changes, element edits, and plugin state. The current export flattens that history. Stable object IDs and atomic edit transactions would preserve more of it than `renderOnlyWhenLatest`. `H/TimeMachine.cs:55–113,215–231,249–302`; `U/UInkIccMapper.cs:29–32,104–125`
- **Clear and Erase need a defined lower-tier rendering path.** The checked-in reader skips the current v10 Clear block and converts Erase Ink to a visible stroke. ICC’s own clear command also preserves selected media types while removing ink and editable scenes. If those operations move to the **Inkeys add-on**, require a Core-readable final-state representation. `U/UInkReader.cs:89–135`; `U/UInkConversion.cs:83–119,158–163`; `M/MW_FloatingBarIcons.cs:4735–4744`; `M/MW_TouchEvents.cs:904–929`
- **PowerPoint binding is an immediate interoperability issue.** ICC writes a best-effort COM `SlideID`, leaves `hostId` unset, then attaches imported ink by ordinal. UInk 1.0 already specifies stable slide lookup and an unbound state on failure. A useful 1.1 addition is a portable unbound presentation page and typed host anchors. `M/MW_UInk.cs:35–64,177–190,323–342`; `spec/blocks/canvas.md:85–89`

## Current ICC-CE ↔ UInk 1.0 mapping

Single-page saves use `.elements.json` and can write plugin sidecars. The ZIP paths can add `plugins.json`; native whiteboard ZIP restore constructs fresh history entries from saved strokes. `M/MW_Save&OpenStrokes.cs:755–771,819–876,890–964,980–1023,1083–1136,1657–1723,1938–1961`; `M/MW_PluginWhiteboardDocument.cs:154–161,197–207`

## Not representable or awkward in UInk 1.0

### Brush geometry, pressure, and stroke metadata

**High · Standard** for portable brush appearance. **Medium · Standard** for optional pressure. **Low · Full** for richer input channels and opaque metadata.

ICC uses elliptical pens and rectangular highlighters with different width and height. Its highlighter overlap setting changes `IsHighlighter`. Its input pipeline can use sampled pressure or synthesize pressure from speed. UInk 1.0 can carry the resulting centerline and scalar width, and already defines Highlighter compositing and SDR/HDR fallback. It has no registered nib aspect ratio, tip transform, curve-fitting intent, or pressure channel. `M/MW_Colors.cs:805–835`; `M/MW_SimulatePressure&InkToShape.cs:209–221`; `Ink Canvas/Ink/WinRT/WinRTStrokeConverter.cs:53–76`; `spec/blocks/ink.md:29–51,63–82`; `spec/common/color.md:5–29`

**1.1** Keep centerline and visible width in Core. Add a Standard `brush` map with nib shape, aspect ratio, tip orientation or transform, and a defined optional smoothing mode. Add normalized per-point `pressure` as editable input data, with width still authoritative for fallback rendering. Put tilt and time in optional Full channels when producers actually have samples. Reuse the existing Highlighter enum and HDR Color Map. Preserve stroke-specific annotations in namespaced metadata without standardizing ICC’s transient tool flags. If page freeze should travel, use an advisory page `locked` flag. `M/MW_InkFreeze.cs:90–100,385–397`; `Ink Canvas/Ink/WinRT/WinRTStrokeConverter.cs:78–89`

### Editable classroom diagrams

**High · Standard** for basic shapes, groups, and vector paths. **Low · not worth standardizing** for individual classroom-tool enums at this stage.

Lines, dashed and dotted strokes, open arrows, rectangles, circles, and ellipses already have UInk 1.0 equivalents, with leeway in exact arrowhead appearance. Parallel lines, coordinate axes, center and focus markers, hyperbolas, parabolas, cylinders, cones, and cuboids can be rendered with multiple primitives or sampled Ink. UInk 1.0 has no single editable compound object or general curved path. ICC itself commits collections of strokes, and draws cuboid edges separately so individual edges can be erased. `M/MW_ShapeDrawing.cs:114–139,1423–1522,1723–1959,1976–2175,3039–3047`; `spec/blocks/shape.md:26–65,119–141`

**1.1** Keep the existing primitive and dash fields. Add a `Path` geometry with multiple subpaths and quadratic/cubic segments, plus a `Group` with stable child IDs and a shared transform. Individual edges can remain addressable. Where exact arrow appearance matters, add optional marker dimensions. A file can carry an opaque tool descriptor for applications that can reconstruct its construction handles.

### Media layout, editable SVG, and text

**High · Standard** for image fidelity and page-local placement. **Medium · Standard** for portable text. **Medium · Full** for editable scene extensions.

Image bytes, affine placement, opacity, PDF page state, and basic audio/video playback are already representable. ICC’s live elements support scale, translation, and rotation, and its native SVG scene sidecar preserves JSON and transforms. Writing an in-memory bitmap to PNG in the resource pack also fits v1.0. The actual format gaps are portable fit/crop behavior, editable scene structure, and semantic text. ICC’s verified text API yields flattened stroke outlines. `M/MW_ElementsControls.cs:134–143,563–578,749–757`; `M/MW_ImageInsert.cs:601–621`; `M/MW_Save&OpenStrokes.cs:35–56,138–172,249–262`; `Ink Canvas/Plugins/Services/InkTextService.cs:49–109,114–143`; `spec/blocks/media.md:44–95`

**1.1** Retain Media’s affine matrix and add `fit` (`fill`, `contain`, `cover`, `none`), alignment, and an optional source crop rectangle. Define a Standard `Text` block with Unicode text, bounds, style runs, and a static glyph fallback. Use grouped vector paths or a Full, versioned scene extension with a static fallback for editable imports. Require per-page media restoration and mixed content order in Standard conformance. ICC can already retain elements across native page flips via TimeMachine. `M/MW_BoardControls.cs:96–129,252–318`

### Page appearance, dimensions, and roaming

**High · Core** for stable page identity, optional page bounds, and a solid background. **Medium · Standard** for a saved pan/zoom view and active page. **Low · Full** for affine camera and patterned backgrounds.

ICC’s normal board uses a settings-backed solid background and a window-sized drawing surface. Roaming applies translation, uniform scale, and optional rotation to content, including images, and records stroke edits. UInk 1.0 supports world coordinates with pan and uniform zoom, but Canvas has no independent document bounds or background. Rotation can be baked into geometry at the cost of recovering the original coordinate system and view. `M/MW_BoardIcons.cs:244–257,277–333`; `Ink Canvas/MainWindow.xaml:228–247`; `M/MW_BoardRoaming.cs:500–565,607–666`; `spec/blocks/canvas.md:15–27,33–63`

**1.1** Define a page descriptor keyed by `pageGuid`, with optional `bounds` and `background.color`. Absent bounds mean an unbounded page. Keep camera state separate from content and page clipping. Reuse `currentPageIndex` or store `currentPageGuid` so reordering preserves the active page. Reserve `viewTransform` and pattern fields for Full. A patterned grid is a proposed extension rather than a verified ICC requirement.

### Multiple workspaces, mini-whiteboard, and layers

**Medium · Full** for nested workspaces, multiple display targets, and layers.

ICC’s owned mini-whiteboard window keeps its own pages, undo histories, dimensions, and opacity. UInk 1.0 already has the structural pieces for its pages and placement in a parent Workspace and Window Device. ICC’s UInk path exports a single Workspace and imports one root, so the current loss is mostly integration. Window opacity has no registered field. `M/MW_MiniWhiteboard.cs:103–104`; `Ink Canvas/Windows/MiniWhiteboardWindow.xaml.cs:21–52`; `M/MW_UInk.cs:31–43,234–245`; `spec/blocks/device.md:57–72`; `spec/blocks/headerExtension.md:39–66`

**1.1** Retain the existing trees at Full, add optional Window `opacity`, and define a Core projection per logical page. Core must be able to enumerate ordered pages, including empty pages, without implementing host-window composition. A file that needs layered composition should carry a compatible projection or declare the feature required.

### Presentation host binding

**High · Standard.**

ICC’s native PPT store uses per-slide ISF and a deck-specific folder. The legacy ZIP import checks a saved deck path by hash when available. The UInk adapter lacks that check and binds by ordinal. UInk 1.0 already provides `hostId` plus COM `SlideID`, including a rule to preserve unmatched content unbound. Its mandatory COM anchor is awkward when a host integration exposes an ordinal, deck name, and path but has no slide ID, as in the checked-in agent state contract. `H/PPTInkManager.cs:470–475,558–575`; `M/MW_Save&OpenStrokes.cs:1565–1580`; `M/MW_UInk.cs:177–190,323–342`; `InkCanvas.PPTAgent.Contracts/PptState.cs:5–10`; `spec/blocks/canvas.md:85–89`

**1.1** Add a typed `hostAnchor` with provider, deck ID, slide ID, and optional ordinal hint. Allow an explicitly unbound presentation page with the same Core rendering as any page. Require a deck and slide match or explicit rebind before publishing ink into a live show.

### Undo, replacement, erasure, and Clear

**High · Core** for final geometry. **High · Standard** for portable edit transactions. **Inkeys add-on** for the Inkeys-specific mask and Clear replay rules.

ICC supports whole-stroke removal and point erasure, including a geometry eraser with elliptical or rectangular footprints that replaces hit strokes with fragments. It also performs partial erasure or removal of editable SVG scene children. Its TimeMachine records before/after geometry and styles, original and recognized strokes, element operations, and plugin changes. UInk 1.0 can save final survivors and fragments, but its append-only Erase is a visibility operation on prior Ink/Shape and leaves Media untouched. `renderOnlyWhenLatest` can approximate a trailing correction, but it cannot identify arbitrary originals replaced in a later edit. ICC clear can preserve images and audio/video, remove editable scenes, and optionally discard history. `M/MW_Eraser.cs:111–141,196–222,257–327,659–680`; `H/TimeMachine.cs:55–113,215–231,265–302`; `M/MW_FloatingBarIcons.cs:4735–4744`; `M/MW_TouchEvents.cs:904–929`; `spec/blocks/ink.md:85–108`; `spec/blocks/clear.md:19–47`

**1.1** Use stable `objectId`s and atomic Standard transactions with add, delete, replace, and update operations. A shape correction or erasure can remove originals and add results in a single reversible transaction. Keep the current scene readable without replaying history. For the add-on, define explicit mask targets and a Clear scope such as `all` or an object-kind filter. Require an authoritative Core projection for files whose visible result depends on those operations. Cross-session Redo is low priority for this integration because ICC’s page-history export already discards the redo tail. ICC’s ink replay also uses sample order and synthesized delays, so it provides no evidence for requiring a recorded timeline. `H/TimeMachine.cs:153–159`; `M/MW_FloatingBarIcons.cs:1676–1717,1737–1754`

### Plugin state and selection

**Medium · Full** for opaque extension data. **Low · not worth standardizing** for runtime controls and active selection.

ICC’s page providers capture and restore strings by page and plugin ID. Plugins can also insert arbitrary interactive WPF controls that live in session history. Active selection consists of runtime stroke and element references; committed geometry edits are a separate portable need. UInk 1.0 `extra` can carry an agreed private payload, but it has no shared namespace, schema, or preservation contract, and ICC reads string-valued extras only. `InkCanvas.PluginSdk/IWhiteboardDocumentService.cs:31–63,65–83`; `InkCanvas.PluginSdk/ICanvasElementService.cs:7–22`; `M/MW_SelectionGestures.cs:839–840,1534–1575`; `U/UInkFormatters.cs:93–119`; `spec/blocks/headerExtension.md:106`; `spec/type.md:39–47`

**1.1** Define a Full extension envelope with namespace, schema version, page or object scope, opaque bytes or a resource reference, and optional portable visual fallback. Allow editors to preserve the envelope without executing it. Keep format registration, live controls, and active selection in host session state.

## Rule-level pain points

| Rule | ICC friction and proposed 1.1 treatment |
|---|---|
| **`contentId` and `undoId`** | v1.0 starts both sequences at zero per Canvas. ICC initializes `contentId` outside the page loop and the writer emits it unchanged, so a later nonempty Canvas can begin with a nonzero ID. The exporter also gives all blocks in each Canvas `undoId = 0`. Keep stream order separate from stable identity and optional transaction grouping. Add fixtures for multiple nonempty pages and mixed-content transactions. `U/UInkIccMapper.cs:104–125`; `U/UInkWriter.cs:42–52`; `spec/file/main.md:55–61` |
| **`renderOnlyWhenLatest`** | It depends on the tail of the stream, skips Media, and stops at Clear. ICC’s adapter filters to convertible Ink/Shape, computes a visible set for every prefix, and records additions and removals separately. That creates potentially quadratic work and can split one correction into two undo steps. Use explicit transaction targets for new files and preserve v1.0 semantics when importing. `U/UInkUndoAdapter.cs:37–83,125–139`; `spec/blocks/ink.md:85–98` |
| **Append and recovery** | v1.0 permits appending to the last Canvas or creating a new Canvas with existing registries. Editing earlier pages, moving objects, changing PDF pages, or altering viewport requires a rewrite. ICC’s append helper has no production caller found, assigns each block its own group, starts an empty Canvas’s first `undoId` at 1, and appends without obtaining a safe truncation offset. Keep append optional. If 1.1 supports append to arbitrary pages, use complete, committed transactions keyed by `pageGuid`, with a recoverable checkpoint. `U/UInkAppend.cs:18–46`; `U/UInkReader.cs:32–50,152–158`; `U/UInkWriter.cs:62–71`; `M/MW_UInk.cs:96–105`; `spec/incremental.md:9–16,32–65` |
| **Implicit singletons, registries, and identity** | v1.0 permits a small file with implicit Device and Workspace, but the implicit Workspace defaults to annotation, and ICC restores multiple whiteboard pages only if the Workspace type and current UI mode agree. ICC’s export regenerates file, Workspace, Device, and page IDs. This is appropriate for fresh exports; a future same-document save needs to preserve them. Define a neutral Core document with stable pages independent of display registration. `M/MW_UInk.cs:31–98,234–257`; `U/UInkIccMapper.cs:39–55`; `spec/blocks/header.md:46–50`; `spec/blocks/headerExtension.md:26–37`; `spec/blocks/canvas.md:65–75` |
| **Viewport and point coordinates** | v1.0 makes layer 0 authoritative for the page/device viewport. ICC bakes the transform into visible and undo strokes while media restoration omits it. Its Ink converter also casts deltas to float32 and accumulates them in float32, which can accumulate error on long paths. Specify a common camera composition for all objects and conformance examples with negative origins, zoomed brushes, and media. Recommend float64 accumulation for v1.0 deltas. Consider optional absolute or periodically re-anchored points only if round-trip measurements justify them. `U/UInkIccMapper.cs:155–178,193–220`; `M/MW_UInk.cs:372–423`; `U/UInkConversion.cs:41–56,108–117`; `spec/blocks/canvas.md:29–63`; `spec/blocks/ink.md:63–82` |
| **Exact MessagePack typing and block recovery** | ICC explicitly writes fixed-width integers, but its reader casts floats to integers and float64 to float32 without checking exactness, accepts integer booleans, and does not reject duplicate known Ink keys. A formatter exception stops the stream even after the object boundary is known. Keep a canonical writer encoding, supply byte-level fixtures for invalid coercions and duplicate keys, and specify recovery separately for framing and field validation. `U/UInkFormatters.cs:27–84,615–624,811–861`; `U/UInkReader.cs:78–87,138–141`; `spec/type.md:19–33`; `spec/conformance.md:20–36` |
| **Media ZIP packaging and commit** | ICC implements resource-first replacement, but new bytes win when an old and new resource share a path. The old main file can therefore resolve different bytes before the new main commits. The importer also caches by basename across documents. ZIP writing normalizes names independently of the emitted Media path; extraction checks declared sizes and overwrites duplicate paths. Use immutable, content-addressed resource names, verification of actual byte counts, consistent reference normalization, and per-resource failure handling. Require a fixture for interruption between resource and main-file commits. `M/MW_UInk.cs:138–173,369–370`; `U/UInkSaveService.cs:33–51,81–129`; `U/UInkExtraArchive.cs:26–61,73–101`; `spec/blocks/media.md:25–42,160` |
| **Tier signaling and safe saves** | ICC skips unknown blocks and rebuilds output from WPF objects, so load followed by export can lose content it skipped or approximated. A lower tier needs enough information to decide whether it can render and safely save a document. Define required features per section and fallback rules for features that change visibility. Preserve unknown data where practical, or surface a lossy export explicitly. In particular, skipping a Clear while displaying the original pre-Clear content gives the wrong page. `U/UInkReader.cs:89–135`; `M/MW_UInk.cs:27–105,227–257`; `spec/type.md:41–47`; `spec/conformance.md:38–44` |

## Uncertain / not verified

- **Static review only.** No files were modified. I did not build, launch ICC, run fixtures, or perform binary round trips. Pressure and delta fidelity, mixed-DPI placement from `Screen.Bounds`, decoder behavior, and overwrite effects are source findings or inferences from the cited code. `U/UInkConversion.cs:41–56,103–119`; `U/UInkIccMapper.cs:39–55`; `U/UInkExtraArchive.cs:73–101`
