## 5. 未答复的两个问题（我的解释和建议）

### 5.1 倾斜的矩形

第五版里那块矩形是“画布”，也就是软件里写字的那块屏幕。墨迹在代码里确实和它一起倾斜，但画面没有表达出来：

- 矩形上没有任何参照物（纯色、没有内容），墨迹又是一条随意的曲线，看不出近大远小；
- 光标和底部字幕是平贴屏幕的，和斜着的矩形是两套透视；
- 我把矩形缩小到能看见四条边，它就从“整个画面在倾斜”变成了“一块漂在底上的板子”。

Google 那支片子倾斜的是**铺满画面、伸出画外的真实界面**，界面上成行的文字让人一眼看出是斜的；它不是一块能看到四周背景的小矩形。

建议的方向（待用户确认）：画布铺满并伸出画面；画布上要有能体现透视的内容，例如多行手写、已有的板书，或白板的点阵；光标要么跟着画布倾斜，要么在倾斜的镜头里不出现。

### 5.2 配色

纯红 `#ff1000` 压在饱和的深蓝上互相抢；再加橙色和浅青，一共四种互不相干的颜色；那套蓝也不是官网的颜色。

建议（待用户确认）：保留红色（它是 Inkeys 画笔的默认色），底色换成中性色（官网深色主题的 `#0f0f0f` / `#1b1b1b`，或浅色纸面）；预测和笔锋不另起颜色，用同一个红色的浅一档。全片只有“底、白字、红”三样。如果用户坚持墨蓝底，那就该换墨的颜色，这一点要用户定。

另一个上一轮问过、用户没回答的问题：预测和笔锋用两种颜色，还是共用一种。

## 6. 第五版用的文字描述（用户没有反对的部分）

全片只有三种镜头，交替出现：

1. **幕标题**：纯底上，词一个一个带弹性地蹦出来，最后并排停一拍，约 1 秒。
2. **功能小标题**：功能名先以大字出现在正中约 0.4 秒；随后字缩小落到底部成为字幕，画面同时从字的后面出现。建议让小标题和画面重叠（字还没落到底，已经开始写），否则 30 秒里 3 个幕标题加 9 个小标题会占掉约 6.5 秒，每个功能只剩约 2 秒。
3. **画布演示**：只有一张画布，在上面写字。镜头不动，动的是画布：每个功能换一个倾斜角度，换的过程就是转场；要看细节时画布转正并放大。

每个功能怎么表现（不加框、不加圈、不出现笔）：

| 功能 | 做法 |
|---|---|
| 多层画布 | 几张倾斜的画布叠着错开，一张一张落下来合成一张 |
| 局部刷新 | 刚画出来的那一小段更亮，像湿墨的反光，随后柔和地退回正常；其余部分不动 |
| 超低延迟 | 光标快速移动，墨迹紧贴光标，没有空隙 |
| 墨迹预测 | 光标前面多出一小段另一种颜色的墨；光标到达后变回正常颜色 |
| 多指书写 | 几个光标同时写，各出各的笔迹 |
| 实时笔锋 | 最前端正在变细的那一段是另一种颜色，定形之后变回正常颜色 |
| 快细慢粗 | 同一笔里快的地方细、慢的地方粗 |
| 手抖修正 | 先出现一条抖的浅色线，墨沿着它写出来却是顺的 |
| 抬笔修正 | 抬笔的瞬间，笔迹末端收成一个干净的笔锋 |

## 11. 实现时的注意点

- 软笔模型（`src/ink/softPen.ts`，示意参考）：
  - 慢则粗、快则细，1.4 倍到 0.8 倍；
  - 最前端最近 55 ms 收成笔锋，逐帧实时计算，不用遮罩揭开终帧；
  - 起笔不渐细；
  - `softStrokeAt(stroke, time)` 的第二个参数是秒。
- 现有 `softPen.ts` 和软件源码有出入（宽度低通是线性近似）。用户说示意即可，看着自然就行。
- 墨迹预测：约向前 1/60 秒，下一帧被替换；抬笔后只留真实笔迹。片子里可以夸大到看得清。
- 倾斜的平面用 CSS 3D 变换时，把平面做得比画面大再缩小，避免放大后墨迹发虚。
- 本机环境：
  - Windows ARM64；Remotion 走 `scripts/run.mjs`，它会用 `.cache/node-x64/node.exe`；
  - 抽帧不要接管道，输出重定向到文件，每张约 16 秒以上；
  - 系统 `python` 有问题，用 `python3`；运行 Trellis 脚本时加 `PYTHONUTF8=1`；
  - ffmpeg 在 `D:/Project/Resource/ffmpeg/ffmpeg.exe`，不在 PATH 里；
  - 用 sed 或脚本改过的文件，再用编辑工具前要重新读。
- 协作规则见用户的全局 `CLAUDE.md`：用简体中文交流、最小改动、关键逻辑加中文注释、未经授权不提交不推送、不启动 GUI、默认不调用 Codex。
