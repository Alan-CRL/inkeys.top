# new-index3 展示内容重新规划

## Goal

`/new-index3` 首屏以下推倒重建。本任务**只规划展示内容**：逐场景用文字描述背景、布局位置、文案、宣传图片与媒体设计，交付一份给用户审阅的 [content-plan.md](./content-plan.md)。视觉样式细节、动效实现与代码改动均后置到后续任务。

## 背景与问题（用户 2026-11-16 判断）

- 现有首屏以下内容没能让新访客快速知道“Inkeys 是什么、对我有什么用”，核心价值没有放在最前。
- 缺少引导下载的节奏：展示内容第一，样式与美观第二。
- 前期过于着急，效果不理想；除首屏外的现有模块（巨型墨迹、图层拆解、占位场景、下载收尾）均不作为约束保留。

## Requirements

- R1 内容顺序以用户草案（`D:\Personal\Downloads\官网布局.txt`）为骨架：首屏艺术字 → 介绍横幅 → 场景化叙事（任何地方批注 → 教室/会议室大 UI 与白板 → PPT 演示 → 画布、笔迹与设备）→ 再次下载 → 画廊 → 功能卡片（通往以后的功能介绍页）。
- R2 场景化叙事抓住不同人群的需求但不点名人群，同时恰到好处地覆盖主要功能。
- R3 每个场景需写清：目的、背景与布局（位置关系、桌面与窄屏）、完整文案草稿、媒体设计（类型、画面内容、动态方式、素材来源）。
- R4 现有大舞台合成图（概览、多样笔触、教学展示图）移到置底画廊；上方介绍区改用更通用、可动态的素材。
- R5 参考同类软件和用户喜爱的官网（ClassIsland、xmaid 等）吸引用户和引导下载的做法，结论写进文档。
- R6 功能描述以 Inkeys dev 代码和新版 README 为事实来源。官网与软件同期上线，文案中不出现“未来实现”“尚未支持”之类的说法。
- R7 无法自行确定的产品、品牌决策，通过对话向用户提问；文档中列出待确认项。
- R8（2026-11-16 用户反馈）不使用滚动进度驱动动画：改为时间驱动自动播放，配可点击的步骤切换和暂停，离开视口暂停，不劫持滚轮。媒体可以破框，与网页融合。
- R9（2026-11-16 用户反馈）文案面向普通用户：不放性能数字，不堆底层术语（RTS、ROT、COM、dev 分支等），不解释显而易见的事；可以适度使用“C++”“Direct3D”等大众熟悉的专业词。
- R10（2026-11-16 用户反馈）亮点融进场景介绍，不单独设“特写”区块；手抖修正、实时笔锋、墨迹预测等技术细节放到以后的功能介绍页（入口为顶栏和主页卡片）。首屏下方不放用户数等数字，Star 与项目规模在页尾介绍开源时顺带展示；不显示版本号；不做网页模拟书写，装饰性墨迹只在控件上点缀。

## Acceptance Criteria

- [x] `content-plan.md` 覆盖全部场景，每个场景都包含目的、布局、文案、媒体四项。
- [x] 文档包含竞品与参考官网的分析摘要，以及据此采用的做法。
- [x] 文档列出素材清单（可复用的已有素材和需要新制作的素材）与待确认问题。
- [x] 不修改网站代码、不发布素材、不提交。

## Out of Scope

- 视觉样式 token、动效参数、组件实现。
- Trellis 历史记录补齐、三个占位场景的素材制作（用户已明确延后）。
- 宣传片制作（草案中的宣传片脚本与网页叙事同源，可共用结构，但本任务不制作）。
